> 面向**配音（TTS 或真人代录）**的版本，与 `video-script.md` 的区别：那个是"边操作边讲"的口播稿，

## 一、开工前：先修两件事，否则镜头会露怯

**① 10 件物品的描述全是同一句话**（`邻居家闲置，物品情况如标题所示，欢迎同小区自提。`）

这会直接毁掉三个镜头：S3 详情页的描述区、S5 发布页、S6 的 AI 定价与文案优化 ——
**AI 拿不到成色信息，定价只能瞎猜；文案没有前后对比，看不出价值。**
把 `backend/app/seed.py` 里的描述换成附录 A 的 10 句真实描述。

**② 清掉测试残留**
身份弹窗里现在能看到一个多出来的住户（手动测试留下的）。跑一次：

```bash
cd C:\Users\XOS\Desktop\ai笔试\backend && uv run python -m app.seed --reset
```

**③ 确认 AI 走的是真模型，不是兜底**
你的 `.env` 指向本机 `127.0.0.1:8080`（自建中转）。**这个服务一挂，三个 AI 功能全部退化成规则回复**，
而"对大模型的熟悉"是评分项。录屏前先调一次定价建议，确认返回里 `source` 是 `"llm"`：

```bash
curl -s -X POST http://127.0.0.1:8000/api/llm/price-suggest \
  -H "Content-Type: application/json" -H "X-User-Id: 6" \
  -d "{\"title\":\"电磁炉\",\"description\":\"用了两年，加热正常\"}"
```

看到 `"source":"llm"` 才算准备好；如果是 `"fallback"`，先修中转，或把 `.env` 换成阿里云百炼。

**④ 录屏画面设置**
这是移动端优先的产品。两个办法，任选：

- **推荐**：Chrome 打开 `http://127.0.0.1:5173` → `F12` → `Ctrl+Shift+M` 进设备模拟 → 选 iPhone（430×932）→ 录屏时只框住模拟区域
- **省事**：把浏览器窗口宽度拉到 **520–560 px**（别低于 520，Chrome 布局视口最小约 504，再窄右侧会被切）

**⑤ 身份先切到「刘同学」**。下面所有镜头都基于这个身份，换成别人权限会不对。

### S8｜架构与数据库设计　2:54 → 3:47　232 字　52.7 秒

> 技术上，前端用 React 加 Vite 和 TypeScript，后端用 Python 的 FastAPI 框架，数据库是 SQLite，通过 SQLAlchemy 访问。前端的请求统一经过 Vite 代理转发到后端，两边完全解耦。数据库按业务拆成四张表，住户、物品、想要关系和留言。物品表上还固化了四条数据库级约束。第一，只有标价物品能有价格，标价就必须填价格。第二，物品状态和送出时间必须同时成立。第三，送出时间不能早于发布时间。第四，只有已送出的物品才能指定接收人。把这些规则放在数据库层，即使请求绕过前端校验，数据也不会自相矛盾。

## 三、拍摄顺序（**重要：不是按叙事顺序录**）

### 为什么打乱

叙事顺序是 S1→S10，但**录屏要按"页面"分组**。原因很实际：每次跨页导航都要重新加载、等接口返回、重新找位置，反复跳来跳去会不断录到加载态和滚动跳动，后期很难裁。**同一个页面内的所有镜头一次录完，剪辑时再按叙事顺序拼**，这是最省时间的做法。

### 一次录完，分 8 组

| 组 | 页面 | 具体操作 | 对应配音 | 预计 |
|---|---|---|---|---|
| **G1** | 列表页 | ① 默认流：从顶部下滚两屏。<br>② 点「免费送」筛选，停 2 秒。<br>③ 搜索框输入「书」，出结果停 2 秒。<br>④ 清空搜索、切回「全部」。<br>⑤ 切「已送出」tab，下滚看归档。<br>⑥ 切「我的」tab，停 2 秒。 | S2 全部<br>S7 中段 | ~60s |
| **G2** | 详情页（**电磁炉**） | 从列表点电磁炉 → 缓慢下滚一遍（图 / 徽章 / 标题 / 描述 / 发布者 / 想要数 / FAQ / 留言）→ 点 FAQ 的「还在吗？」等出结果 → 点心形「想要」，停 2 秒看数字变 → 留言框输入一句发出 → 滚到底看新留言。 | S3 + S4 | ~70s |
| **G3** | 发布页 | 底部「发布」→ 空表单全景停 1 秒 → 输入名称和一句描述 → 点「获取定价建议」等结果 → 关闭 → 点「优化文案」等结果 → 点「采用」回填 → 选「免费送」→ 提交。 | S5 + S6 | ~90s |
| **G4** | 详情页（**刚发布的那件**） | 提交后自动跳转，不用切页。上下滚一遍即可。 | S5 结尾 | ~10s |
| **G5** | 详情页（**小电扇**）+ 标记送出 | 底部「闲置」→ 切「我的」→ 点小电扇 → 点「标记已送出」→ 弹窗选「赵姐」→ 确认 → 停 2 秒看"已送出"角标。 | S7 前半 | ~45s |
| **G6** | 数据看板 | 底部「看板」→ 停住 5 秒（让三个数字和两个榜单都看清）。 | S7 后半 | ~25s |
| **G7** | 身份弹窗 | **放最后录**（会清掉登录态）：无痕窗口打开 `5173` → 弹窗出现 → 停 2 秒 → 选一个住户。 | 备用 / S1 可选 | ~15s |
| **G8** | 静态素材 | 不录屏，直接做图：架构图、ER 图导出 PNG、"做了/砍了"对照图；可选录一段后端 `uvicorn` 启动日志。 | S8 + S9 | — |

### 这个顺序里有 4 个坑，都躲开了

**① 演示"点想要"必须用「电磁炉」，不能用「婴儿推车」。**
「刘同学」这个身份**已经点过婴儿推车的想要了**，进去按钮显示的是「已想要」，你点下去是**取消**，讲"点一下就能表达想要"会对不上画面。
电磁炉是唯一合适的：未点过想要、有 3 个人想要（数字变化明显）、有 1 条留言、还是在售。

**② 「婴儿推车」适合拍静态镜头，不适合拍操作。**
它内容最丰富（2 条留言、4 人想要、免费送），可以补一个 5 秒的"已想要状态 + 留言板"镜头，但别在这里演示点击。

**③ 标记送出用小电扇，不用刚发布的那件。**
「选择接收人」这个功能要有候选人才演得出来。小电扇（刘同学自己发的）**有 1 个人想要（赵姐）**，弹窗里能真选；
刚发布的物品没人想要，弹窗是空的，这个功能就白演了。

**④ G7 身份弹窗必须最后录。**
它会把 localStorage 里的身份清掉，录完要重新选一次身份，会打断前面所有镜头的前提。

### 音量与节奏提醒

- 每组**多录 3–5 秒头尾**，方便剪辑对齐
- 一天里光线/浏览器缩放保持一致，避免拼接时画面跳变
- 每组录完后**立刻用文件名记下这组的时间点**（如 `G2-1分管12秒-点想要`），剪的时候找得快

## 四、配音制作要点

### 4.1 TTS 参数

| 项 | 建议 |
|---|---|
| 语速 | **1.0**（按 4.4 字/秒 = 约 260 字/分调）。整体偏快就调 0.95，偏慢调 1.05 |
| 调节原则 | **十段用同一个语速**，不要逐段微调，否则音色节奏会不统一 |
| 音色 | 温和、沉稳的成年男声或女声。避开播音腔过重的音色，产品讲解要像"人在说话" |
| 停顿 | 段内逗号句号交给 TTS 自动处理；**段与段之间不要靠 TTS，靠剪辑留 1 秒空白** |
| 输出 | 十段分开导出：`01-开场.mp3` … `10-收尾.mp3` |

### 4.2 试听时重点听这几个词（TTS 常念错）

| 词 | 风险 | 处理 |
|---|---|---|
| `FastAPI` | 可能连读成"法斯塔皮" | 试听；不行就改写成 **Fast A P I** 三段念 |
| `SQLite` | 可能念成"赛口莱特"或逐字母 | 试听；不行改成 **轻量数据库 SQLite**，或直接说"轻量数据库" |
| `SQLAlchemy` | 大概率念错 | **最稳妥：把这句改成"通过 ORM 框架访问"** |
| `React` `Vite` `Tailwind` `TypeScript` | 一般正常 | 试听一次，正常就留 |
| `Swift` 以外的英文缩写 | — | 稿里已刻意避开 LLM / RAG / ER 等缩写，不用管 |

> 稿子里所有数字都已写成中文（一天以内 / 三天以内 / 三十到八十块），就是为了避开 TTS 把 `24 小时` 念成怪读法。

### 4.3 时间轴对齐方法（音频先行）

1. 十段配音全部生成好，按 S1→S10 顺序铺进剪辑软件
2. 每段之间留 **1 秒空白**（TTS 念完到下一段开头）
3. 音频总长应落在 **4:57** 左右。偏差超过 ±10 秒，就回 TTS 调语速重出，**不要靠拉伸音频硬凑**
4. 然后把 G1–G7 的录屏素材，**裁成对应段落的长度**贴到音频下方
5. AI 等待、页面加载的片段，用**剪掉或 4 倍速**处理，别让它拖长
6. S8 / S9 用静态图 + 圈注，不需要录屏

### 4.4 字幕

配音稿本身就是字幕稿。按 4.4 字/秒切行、**每行不超过 18 字**，可以直接生成 SRT，
或者用剪辑软件的"自动识别字幕"后再按稿子校正。

## 五、附录 A：10 件物品的真实描述（直接替换 `seed.py` 里那句占位文案）
